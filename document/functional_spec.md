# 機能仕様書：GpsPressureLogger

最終更新: 2026-04-16

## 1. 概要
GpsPressureLogger は、Android 端末上で GPS・気圧・歩数を時系列記録し、グラフと地図で閲覧できるロガーです。通常運用では端末内の Room DB を正規データとして保持し、必要に応じて標準 CSV を import / export します。

## 2. 使い方

### 2.1 通常記録
- フォアグラウンドサービス `LoggingService` を起動すると、気圧・GPS・歩数センサーの観測値を継続記録する。
- 主記録周期は現行仕様では 3 秒固定で、設定画面から変更しない。
- 設定画面の `表示する期間` は `6h / 12h / 1d / 2d / 3d / 1w` の選択式とし、既定値は `3d` とする。
- 端末再起動後とアプリ更新後は、`LoggingService` を自動再開する。
- 調査用に、端末終了、端末再起動、アプリ更新後再開のトリガをデバッグログへ記録する。
- GPS が取得できない時刻でも、気圧や歩数のみの行を保存できる。
- 記録値の閲覧はホーム画面のグラフと地図画面で行う。
- 日常ログ CSV は app-specific external storage を優先して `GpsPressureLogger/logs/` に保存する。
- 日常ログの 1 日境界は 00:00 ではなく 03:00 とする。

### 2.2 エクスポート
- 設定画面から「全ログを保存」を実行すると、標準バックアップ CSV を 1 ファイル生成する。
- 設定画面から「補助センサー判定ログを保存」を実行すると、補助ログバックアップ CSV を 1 ファイル生成する。
- 出力形式は `Timestamp,Lat,Lon,Alt,PresRaw,PresQnh,StepsDelta,GpsAccuracy` の標準 CSV に統一する。
- 重要な運用イベントは、日次 CSV と手動バックアップ CSV に `#` コメント行としても残す。
- 詳細なデバッグログ本文は別ファイルとして扱う。

### 2.3 インポート
- 設定画面で読込元の標準バックアップ CSV ファイルを選択し、そのファイルを import する。
- 設定画面で読込元の補助センサー判定ログ CSV ファイルを選択し、そのファイルを import できる。
- インポート対象は標準バックアップ CSV のみとする。
- 読み込み対象ファイル名は `gps_pressure_full_backup*.csv` とする。
- 既存 DB と `Timestamp` が衝突した場合は、「上書きする」または「既存を優先する」を選択できる。
- 対象外ファイル数と解析エラー数は、インポート完了時に利用者へ通知する。

### 2.4 デバッグログ共有
- 設定画面でデバッグログ出力先ファイルを選んだうえで、Google ドライブ向けデバッグログ送信を ON にできる。
- ON の間は、重要なデバッグログをローカル保存に加えて選択済みログファイル URI に追記する。
- 同じ重要イベントは、日次 CSV と手動バックアップ CSV にも `#` コメント行として反映される。
- 未捕捉例外が起きた場合は、要約を `# EVENT ... UNCAUGHT_EXCEPTION ...` として日次 CSV / 手動バックアップ CSV に残す。
- 高頻度な詳細デバッグログは、設定画面の `詳細デバッグログ` を ON にした時だけ出力する。
- 必要に応じて「デバッグログを今すぐ送信」でローカル debug ログ全体を手動送信できる。
- 必要に応じて「DB サマリをログ出力」で、端末内 DB の最古・最新・日別件数・0時台件数をデバッグログへ出力できる。
- 調査時はホームグラフのサイズ、ドラッグ量、ズーム量もデバッグログへ出力できる。
- 調査時はサービス受信トリガ、`onStartCommand()` 到達、初回記録成功もデバッグログで追跡できる。

## 3. 機能仕様

### 3.1 記録機能
- 気圧、海面更正気圧、GPS 緯度経度、高度、歩数増分を時系列で保存する。
- 主記録の論理生成周期は 3 秒とし、主記録は 3 秒スロットごとに 1 レコードを持てるものとする。
- 主記録では GPS / 高度 / 気圧 / 歩数増分の欠損を認め、欠損列は空欄または `null` として扱う。
- モード判定用の補助指標として、`KStatus`、`KAvg`、`KVariance`、`WStatus`、`StepDeltaWindow`、`GpsIntervalMs`、`ConfirmedMode`、`ConstantRegionKind`、`ConstantRegionSpeedKmh`、定速領域の始点・終点・stay point・方向を 3 秒ごとに別ファイル・別保存で記録する。
- `AccelStddev3s`、`AccelMad3s`、`StepDelta3s`、`StepRate3s` は旧方式互換列として残すが、新方式では空欄を許容する。
- 主記録と補助指標は、平常時はメモリ上のキューへ蓄え、日次 CSV などファイル系ストアへの書き出しは既定で 100 件ごとにまとめて行う。
- Room DB への保存は遅延させず、主記録・補助指標ともに生成時点で反映する。
- ファイル系ストアへの書き出し前でも、手動 export、サービス終了、端末再起動 / APK 更新の受信など失いたくないタイミングでは強制フラッシュする。
- 移動状態に応じて GPS 更新間隔を動的に切り替える。
- 起動時の旧歩数補完処理は毎回ではなく、必要な移行バージョンで一度だけ行う。
- 端末再起動と APK 更新では `BootReceiver` が `LoggingService` の再開を試みる。
- 移動状態は `完全停止`、`停止`、`徒歩`、`高速移動` の 4 段階で扱う。
- GPS がない時刻も、気圧や歩数のみの部分レコードとして保持する。
- 歩数は `StepsDelta` として保持し、表示時に 03:00 区切り日単位で集計する。
- 歩数グラフは、03:00 区切り日ごとに 0 から積み上がる系列として表示する（前日分の続きではない）。
- `PresQnh` はその時刻に有効な GPS 高度がある場合のみ保存する。
- 歩数センサーは、徒歩状態判定の強化要素として使う。
- 加速度状態は `Sensor.TYPE_LINEAR_ACCELERATION` を優先して判定し、未対応端末では raw accelerometer から重力差分ノルムを fallback として使う。
- 歩行状態は直近 9 秒の歩数増分から `W1 / W2` を判定する。
- `完全停止` は、携帯が置かれていてほぼ触られていない状態を表し、通常の `停止` より強い省電力制御候補とする。
- `K4` は直近 1 秒の合成加速度平均 `KAvg > 0.70` で判定し、高加速・減速・旋回・昇降を表す。
- `K4` への確定遷移には `0.5秒` 以上の継続を要求し、段差などの突発ノイズによる即時誤判定を抑える。
- `K2_K3` は `K4` でなく、合成加速度分散 `KVariance > 0.01` のときに判定し、振動・揺れを表す。
- `K1` は上記以外で、加速度なしまたは極めて安定した等速直線運動を表す。
- `W1` は直近 9 秒の歩数増分が 1 歩以上、`W2` は歩数増分なしとする。
- `完全停止` は `K1 + W2 + stay` を基準に判定する。
- `停止` は `K2_K3 + W2 + stay` を基準に判定する。
- `徒歩` は `W1` かつ `K4` ではない状態を基準に判定する。
- `高速移動` は `K4` または定速領域の `constant move` を基準に判定する。
- 定速領域の `stay / constant move` 判定では、直線近似前に重心から大きく離れた孤立 GPS 点を棄却する。
- GPS 更新間隔は `K4` で即時取得 + 5 秒、`W1` で 5 秒、`W2` で 5 秒から 10 秒、15 秒へ線形に引き延ばす。
- GPS 更新間隔を長くした後でも、`K4` を検知したら待たずに短い間隔へ戻す。
- GPS 更新間隔を長くする方向の切り替えには最小維持時間を設け、短時間の揺れで頻繁に伸縮しないようにする。
- GPS の取得周期とファイル保存周期は分離する。
- GPS は 3 秒スロットごとに集約し、欠損を許容する。
- 移動中（徒歩 / 高速移動）の GPS 集約規則は次のとおりとする。
  - スロット内 GPS プールが 0 件なら欠損
  - スロット内 GPS プールが 1 件ならその 1 件を採用
  - スロット内 GPS プールが 2 件以上なら、直前の採用 GPS `before` とプール内 GPS 群からスプライン補間を作り、そのスロット時刻の経度・緯度・高度を採用
- 完全停止かつ直前スロットも完全停止のときは、スロット内 GPS プールが 1 件以上あれば `before` を含む平均位置・平均高度を採用し、0 件なら欠損とする。
- 完全停止かつ直前スロットが完全停止ではないときは、スロット内 GPS プールが 1 件以上あれば `before` を含めない平均位置・平均高度を採用し、0 件なら欠損とする。
- 停止 `STOPPED` の GPS 集約は、直前も `STOPPED` または `DEVICE_STILL` なら `before` を含める完全停止寄り平均を使う。
- GPS スロット内補間は 3 次スプラインを基本とする。
- 気圧は 3 秒スロット時点の最新保持値を採用し、センサー未初期化時だけ欠損とする。
- 歩数は 3 秒区間の増分を `StepsDelta` とし、初期基準未確定時は `0` から開始してよい。

### 3.2 表示機能
- ホーム画面で気圧・高度・歩数を統合表示する。
- グラフは横方向の時間軸操作に対応し、左スワイプでより古い時間帯へ移動できる。
- グラフはピンチインで期間を広げると、より古い時間帯まで同時に表示できる。
- グラフのピンチアウトは既定で設定表示期間の最大 2 倍まで表示でき、その範囲の履歴は表示側で先読みする。
- グラフは 1 本指ドラッグを時間移動、2 本指ピンチを倍率変更として分離する。
- グラフの横移動量は、現在の可視期間と表示幅に比例して計算し、感度定数で調整する。
- グラフを古い方向へドラッグした場合、現在画面に読み込まれている最古データで移動を止めず、指を離した時点で端末内 DB の保持範囲に基づいて読込範囲を更新する。
- グラフをピンチで短い期間に縮めた場合、古い方向への移動下限もその短い可視期間を基準にする。設定表示期間が 3 日でも、1 日表示に縮めた状態なら最古データ + 1 日付近まで辿れる。
- グラフのジェスチャ認識は Android 標準のドラッグ / スケール検出器を用いて行う。
- グラフ上部に現在表示中の時間範囲を表示する。
- グラフの表示範囲は、設定された期間を優先し、データが無い区間は空白として表示する。
- 地図画面は 03:00 区切り日単位でログを表示する。
- 地図画面は、日付切替時のみ自動フィットし、利用者が行った手動ズームはその日の間維持する。
- 地図の日送りは、位置データが存在する日だけを対象にし、空の日は自動で飛ばす。
- 地図の日付が変わった時は、データが無い場合でも初期表示（初期中心・初期ズーム）へ戻す。
- 地図ウィジェットは本体地図と同じ日次抽出と GPS 外れ値除去を通した軌跡を描画する。
- 地図ウィジェットの更新は app widget host の長周期更新に依存せず、`LoggingService` からの定期更新で行う。
- 地図ウィジェットとグラフウィジェットのサービス由来更新周期は、`LoggingService` が保持する次回予定時刻で管理し、指定した周期より短くならないようにする。ホスト由来の初回配置・復元・再構成更新は、クリック復旧と表示整合性を優先して描画を許可する。
- 気圧・標高ウィジェットと地図ウィジェットの設定可能な更新間隔は、どちらも `30秒` 以上 `300秒` 以下とする。
- ウィジェット表示用の最新値取得では、全件走査を避けて最新レコード取得 API を優先する。
- 地図系表示では、前後の点へすぐ戻る単発ジャンプを 3 点比較で除去する。
- 地図系表示では、高速移動中の一時的な横飛び点を、前後線分からの横ずれと折れ角でも除去する。
- 地図系表示では、短時間だけ別地点群へ飛んで戻る誤クラスタをまとめて除去する。
- 地図画面の折れ線は、停止点を固定したまま移動区間だけを軽く平準化して見やすくする。
- 地図画面と地図ウィジェットの折れ線には、長い直線区間だけでなく曲線区間にも `>` 風の進行方向マーカーを差し込み、進行方向を読み取りやすくする。
- 地図画面と地図ウィジェットの折れ線色は、`DEVICE_STILL=黒 / STOPPED=グレー / WALKING=青 / VEHICLE=赤` で統一し、旧来の赤青グラデーションは使わない。
- 地図画面と地図ウィジェットでは、定速領域が継続中でも最新の暫定 `ConstantRegionKind` を使って描画する。暫定 `STAY` の区間は stay point 1 点へ畳み、暫定 `CONSTANT_MOVE` の区間は通常の折れ線として描く。
- 地図系表示では、`DEVICE_STILL` と `STOPPED` の区間に対して、モードごとの別パラメータで GPS ブレを表示用に抑える停止標準化を既定で適用する。
- `DEVICE_STILL` の表示補正は、完全停止中の測位ブレを実移動より強く疑う前提で、偏差半径をおよそ `2m` まで強く圧縮する。
- 地図ウィジェットの折れ線も、本体地図と同じ平準化を適用する。
- アプリ地図と地図ウィジェットの折れ線生成は同じ共通関数を使い、viewer を基準に揃えた表示用系列を描画する。
- 開始点と現在点のマーカーサイズは縮尺と独立した固定サイズとし、滞在点は件数に応じた控えめな可変サイズとする。
- サイズルールは app / widget で共通とするが、描画面の違いによる体感差を補うため、面ごとの倍率は共通定数として管理する。
- 開始点は白地に赤リング、現在点は白地に青リングで app / widget とも統一する。
- 現在点の青リングは、開始点の赤リングと同じ線幅で描く。
- 現在値表示で標高や補正気圧が欠損した場合は、直近履歴の有効値を使って `-` 表示を避ける。
- グラフ系列の末尾欠損は、直近の有効値を持ち越す形で補い、標高・補正気圧が `-` だけになる状態を避ける。
- ホーム画面とグラフウィジェットの現在歩数表示は、ラベル・数値とも青で表示する。
- ホーム画面とグラフウィジェットの歩数グラフは、`DEVICE_STILL=黒 / STOPPED=グレー / WALKING=青 / VEHICLE=赤` のモード色で描く。
- グラフの補正気圧系列は白で描く。
- ホーム画面とグラフウィジェットのグラフには、ローカル日付の 00:00 位置へ細いグレー寄りの白い縦線を描く。グラフウィジェットでは現在値エリアや下端余白へ線を伸ばさず、プロット領域内に収める。
- グラフウィジェットの 00:00 縦線には、その線から始まる日付を `M/d` 形式で併記する。
- ウィジェットのグラフ表示範囲は、設定した表示期間を左端から右端まで固定で使い、アプリ初期表示と同じ時間窓を採用する。
- 設定画面で表示期間またはグラフウィジェット透明度を変更した場合は、サービス周期を待たずにグラフウィジェットを強制再描画する。
- 起動時にローカル日次 CSV から旧歩数データを補完し、既存端末データでも歩数表示を維持する。
- Windows viewer では、地図の停止標準化を `ON / OFF` で見比べながら表示確認できる。
- Windows viewer では、読み込んだバックアップ内の `日付` を選び、グラフ・地図・イベント一覧をその日付に切り替えて確認できる。
- Windows viewer では、`stepsDelta=0` かつ `VEHICLE` ではない短時間の `復帰バースト` と `偽クラスタ滞在` を前段で検知し、前後の正常クラスタへ戻す表示補正を試験適用できる。
- Windows viewer の `補正あり` は、Android アプリ本体と地図ウィジェットの固定描画順序 `復帰バースト / 偽クラスタ滞在 / 停止標準化 / GPS 平準化` を再現する。
- Windows viewer では CSV に `MotionSample` が含まれないため、`# EVENT` の `MODE_CONFIRMED` から Android の確定モード遷移と同じ考え方の表示モード列を再構成する。
- 上記の `復帰バースト / 偽クラスタ滞在 / 停止標準化` は、Windows viewer で検証したうえで Android アプリ本体と地図ウィジェットの**表示用 GPS 系列**にも反映済みとする。
- Android 側でも、取得・保存データは変更せず、地図表示用系列にのみ適用する。
- Windows viewer は、ブラウザ表示版に加えて `pywebview` を使った独立アプリ版でも起動できる。
- 独立アプリ版は表示コンテナだけを差し替えたもので、補正ロジック・グラフ生成・地図生成は HTML 版と同じ dashboard 生成処理を使う。

### 3.3 データ整合性
- 端末内の正規データは Room DB とする。
- `Timestamp` は DB 内で一意とする。
- import 時は同一 `Timestamp` をマージ対象とし、競合解決はユーザー選択に従う。
- 標準 CSV では欠損を空欄で表現する。
- 停止中で新しい GPS コールバックが来ない場合でも、再起動直後や 03:00 境界直後に地図系列が空のまま固着しないよう、表示・記録の両方で直近有効 GPS の再利用と bootstrap 取得を許可する。

## 4. 現時点で把握している注意点
- 日常ログは app-specific external storage を優先するが、外部保存領域が使えない場合は内部保存へフォールバックする。
